# 用語集

記事で使う用語の定義を集約する。新出用語はここに追記し、記事内で長い定義を繰り返さない。

> ⚠️ **本用語集は中立的な概念定義に限定する。** 「どのプランが学習しない」「どれが統制が充実」
> 「どの基盤が境界内で処理しやすい」といった**可変の製品仕様・評価は書かない**（それらは
> 出典・確認日付きで各記事に書く）。ここは語の意味の共有だけを担う。

## AI活用の段階モデル

- **AI活用の4段階モデル（①チャット→②RAG・ファイル生成→③エージェント→④業務プロセスの再設計
  （AI前提））**: 本プロジェクトの記事群が全体のどこに位置するかを説明するための簡易的な整理
  （→[00](../research/00-概要.md)2節）。業界標準のフレームワークではなく、厳密に排他的な
  分類でもない。
- **業務プロセスの再設計（AI前提）**: 4段階モデルの④段階。AIの存在を前提に、既存の業務プロセスの
  構造そのもの（役割分担・判断の順序・承認の要否）が組み替わることを指す。AIを既存プロセスに
  後付けの監視・提案ツールとして追加すること（監査・モニタリングの強化）とは異なる。組織範囲
  （部署内〜複数部署・全社）や対象業務（事務・開発・製造等）はこの段階の発展軸であり、単独の
  判定基準ではない。文脈上明らかな場合は「業務プロセスの再設計」と短縮して表記することがある。

## 組織・読者（対象の概念）

- **小規模IT部門**: 本プロジェクトが想定する読者層（非IT中小企業100〜500人規模のIT担当組織）を
  指す語。「情シス」という呼称は、専任部署・専任要員を前提にした語感が強く、実際には社内SE
  との兼務や1〜数名での運用も多い本プロジェクトの想定読者には必ずしも合わないため、本プロジェクトでは
  「小規模IT部門」を基本の呼称とする。自社で「情シス」「社内SE」等、別の呼称を使っている場合は
  読み替えて構わない。

## プラン・契約（形態の概念）

- **個人プラン**: 各社の Free / Plus / Pro / Max など個人向けの契約形態。
- **法人プラン（Team / Business）**: 少人数〜中規模組織向けの契約形態。
- **Enterprise プラン**: 大組織向けの契約形態。
- **API / 開発者向け**: プログラムからモデルを呼ぶ利用形態。
- （各形態で「学習・保持・統制機能がどうか」は仕様依存。→ [06](../research/06-製品プラン比較.md) に出典付きで記載）

## 事業者・基盤（対象の概念）

- **Anthropic / Claude**: 本プロジェクトが主に想定するAIベンダー／モデル。
- **OpenAI / ChatGPT / Codex**: 記事で同等に扱う比較対象。Codex はコーディング支援。
- **AWS Bedrock**: AWS上でマネージド型に各社モデルを利用する基盤。
- **Microsoft Foundry（Azure AI Foundry）**: Azure上でAIモデル・エージェントを構築・運用する基盤（Azure OpenAI 等を含む）。
- **Vertex AI**: Google Cloud のAI基盤（比較参考）。
- （各基盤の「データがどこで処理されるか」は構成・リージョン依存。→ [07](../research/07-提供方式と出口戦略.md) に成立条件付きで記載）

## データの扱い（区別して使う）

混同しやすい概念を分けて用いる。どのプラン・基盤が実際にどうかは仕様依存であり、記事側で出典・確認日を付ける。

- **学習利用（トレーニング）**: 入力/出力をモデルの学習に使うこと。
- **推論時処理**: 学習とは別に、応答生成のために一時的に処理すること。
- **保存 / ログ / 保持（Retention）**: 会話・データが保存される・ログに残る・一定期間保持されること。
  「学習しない」ことと「保存・履歴に残る」ことは別問題。
- **削除**: 保持期間超過分や依頼に基づく削除。削除の範囲・タイミングは仕様依存。
- **サブプロセッサー（再委託先）**: ベンダーがデータ処理を委託する第三者。DPAで確認する。
- **越境移転**: データが国外に移転されること（個人情報保護法上の整理が必要）。
- **クラウド境界内（要注意語）**: 「自社クラウド内で完結」等は成立条件付き。構成・リージョン・
  サブプロセッサーを確認して初めて言える（非保証事項を明記する）。
- **マスキング**: 対象文字列の一部・全部を固定の記号（`*`等）に置き換える技術的処理。復元不可
  （元の値は破棄される）。情報区分・アクセス制御等の主要統制を代替するものではなく、限定用途の
  補助的統制として使う（→[05](../research/05-セキュリティ法務調達.md)2.3節に出典付きで詳細）。
- **仮名化（Pseudonymization）**: 識別子を仮名（ランダムな値等）に置き換える加工。他の情報と
  照合すれば元の個人の識別に戻せる状態を残す点でマスキング・匿名化と異なる。
- **匿名化（Anonymization）**: 特定個人を識別できないよう加工し、加工前のデータへの復元を
  不可能にする処理。日本の個人情報保護法上の「匿名加工情報」は、単純なマスキングだけでは
  加工基準を満たさない（→[05](../research/05-セキュリティ法務調達.md)2.3節）。
- **トークン化（Tokenization）**: 元の値を代替値（トークン）に置き換える処理。暗号鍵を用いた
  変換（方式によっては鍵を持つ者が復元可能）と、対応表（トークンボールト）で管理する方式が
  あり、復元可能性は方式による（→[05](../research/05-セキュリティ法務調達.md)2.3節に出典付きで
  詳細）。

## セキュリティ・統制

- **SSO（SAML / OIDC）**: シングルサインオン。退職者アカウントの即時遮断に必須。
- **SCIM**: ユーザー・アカウントのプロビジョニング自動化規格。入退社の反映に使う。
- **監査ログ / Compliance API**: 誰が何をしたかの追跡・エクスポート。
- **データ保持期間（Retention）**: 会話・データを保存する期間設定。超過分の削除運用に関わる。
- **データレジデンシー**: データを保存・処理するリージョンの指定（越境移転の整理に関わる）。
- **DPA（データ処理契約 / Data Processing Addendum）**: 委託先としての取り扱いを定める契約。
- **DLP**: データ損失防止。機密情報を検知して警告・ブロックする仕組みであり、値そのものを
  書き換えるマスキングとは別の機構（役割分担は→[05](../research/05-セキュリティ法務調達.md)2.3節）。
  プロンプト内容の完全検査は非現実的な点に留意。
- **CASB / SWG**: クラウド利用の可視化・制御。個人アカウント版のブロック等に使う。
- **RBAC**: 役割ベースのアクセス制御。
- **シャドーIT / シャドーAI**: 会社の管理外で個人アカウントのAI等を業務利用する状態。
  学習対象・ログなし・退職時遮断不能などのリスクを伴う。

## エージェント関連

- **AIエージェント**: 目標に対しツール・コネクタを使って複数手順を自律実行するAI。
- **ローカル操作エージェント（コンピュータ操作型）**: 人間と同じように画面・ブラウザ・キーボードを
  操作して作業を自動化するエージェント。APIが提供されていない画面の自動化に向く。
- **ワークフロー型エージェント（オーケストレーション型）**: あらかじめ設計した手順・複数ツール連携の
  中で、判断が必要な箇所だけをエージェントが担当する構造化されたエージェント。
- **スキル（Agent Skills）**: 指示・スクリプト・参考資料をまとめ、エージェントが必要に応じて段階的に
  読み込んで再利用できるようにする仕組み。
- **スケジュール実行（Routines等）**: 決まったプロンプト・接続先をあらかじめ保存し、定期的な
  スケジュールやイベントをきっかけにエージェントを自動実行する仕組み。
- **コネクタ / MCP（Model Context Protocol）**: 外部データ源・ツールとAIを接続する仕組み。
  許可制にしないと、入力禁止にした文書がAI経由で参照される恐れがある。
- **権限越境（本プロジェクトでの用語）**: 「アクセス権はあるが本来その用途では見ない情報」が、
  エージェントにより横断的に読まれ別文脈へ再出力されるリスク。従来SaaSにはなかった論点。
- **コーディングエージェント**: Claude Code / Codex 等、コード生成・実行を伴う開発支援エージェント。
- **最小権限 / 職務分離**: 必要最小限の権限のみ与える／権限や作業を分離してリスクを抑える設計原則。
- **HITL（Human-in-the-loop）**: 重要な操作にAIだけで完結させず人の承認・確認を挟む運用。
- **プロンプトインジェクション**: 入力や参照データに紛れた指示でAIを誤誘導する攻撃。
- **グラウンディング / RAG**: 外部の根拠情報を参照して回答を裏付ける仕組み。
- **評価セット**: 出力品質を再現可能に測るためのテスト用データ・観点集。
- **サービスオーナー / データオーナー / 責任分界**: そのサービス・データ・責任範囲の持ち主の明確化。

## 運用・投資・リスク管理

- **RACI**: 実行・説明責任・相談・報告先を役割で整理する責任分担表。
- **属人化**: 特定の業務の進め方・ノウハウが特定の個人に偏り、その人が異動・退職すると
  組織として遂行できなくなる状態。（AI活用における属人化リスクの扱いは
  → [11](../research/11-段階導入ロードマップ.md)3.3節）
- **ベースライン**: 効果測定の基準となる導入前の値。
- **TCO（総保有コスト）**: ライセンス以外に教育・運用・監査・開発・レビュー工数まで含めた総費用。
- **残余リスク / リスク受容**: 対策後に残るリスク／それを承認して受け入れること。
- **ロックイン / 可搬性 / 終了支援**: 特定ベンダーへの依存／他への移行しやすさ／契約終了時の
  データ移行・削除確認。
- **見直しのタイミング**: 一定期間（パイロットでは3〜6ヶ月）ごとに、実測データをもとに
  拡大・継続・中止を判断する節目。新規事業開発のStage-Gate手法における「ゲート」に相当する
  本プロジェクトの呼称（旧称「判断ゲート」から統一）。判定ロジックの正本は
  → [11](../research/11-段階導入ロードマップ.md)3.2節（利用範囲拡大・層Aの契約形態変更
  〈Enterprise化〉・層B導入という3つの問いを独立に判定するモデル）。
- **Go / Hold / Stop**: 見直しのタイミングでの「拡大／保留／中止」の判定。

## 会計・投資

- **原価 / 販管費**: 費用の会計区分。AI利用料をどちらで捉えるかで見え方が変わる。
- **投資 vs 費用**: 単なるコスト（費用）でなく、リターンを生む投資として捉える考え方。
- **ROI**: 投資対効果。本プロジェクトでは「削減人時 × 人件費 vs 月額費用」で概算する。

## 認証・規格

- **SOC 2 Type II / ISO 27001 / ISO/IEC 42001**: セキュリティ・AIマネジメントの
  第三者認証。稟議・監査で参照される。取得状況は各社Trust Centerで要確認。
