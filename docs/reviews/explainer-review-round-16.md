## 第1巡

### サブエージェント（事実正確性）の指摘

- **大**: 2.4節の5軸表と2.5節・冒頭の「主要統制」の列挙が3通りに揺れており内部矛盾していた
  （契約・監査の有無、利用目的の扱いが箇所によって異なる）。
- **大**: `ref-google-dlp-vertex`（Vertex AI向けSensitive data discovery）は学習・チューニング用
  データセットの発見機能のみを説明しており、「推論を含むAIライフサイクル全体への加工技術」という
  本文の主張、およびマスキング・トークン化そのものへの言及を裏付けていなかった。
- **大**: 定義表の「トークン化」が、引用元（Google Cloud Transformation reference）が実際に
  説明する暗号鍵ベースの方式ではなく、対応表方式として書かれていた。
- **軽微**: Anthropic「How we contain Claude」の引用範囲（Cowork固有の隔離と製品横断の原則が
  一文にまとまっていた）。
- **軽微**: NIST SP 800-188の仮名化定義が逐語確認未了（確度表示の検討）。

### サブエージェント（説得力・論理構成）の指摘

- **大**: `appendix/interim-guideline.md` の冒頭注記は主従関係を更新済みだったが、本文2節見出し・
  本文が「伏せ字にすれば使える」というマスキング中心の表現のまま残り、冒頭注記と矛盾していた。
- **大**: 2.3節のAnthropic引用が、論点の異なる文書（エージェント権限の記事）の沈黙を根拠に
  ベンダー全体の統制思想を断定しており、論理の飛躍だった。
- **軽微**: `exception-request-form.md` の設問がマスキング中心のまま。記事冒頭の密度がやや高い。
  2.3節の5理由に「事実／見解」ラベルがなかった。

### サブエージェント（分かりやすさ）の指摘

- **大**: Microsoft Purviewの対応状況（監査・DSPM＝対応、分類・ラベル・DLP＝未対応）が表ではなく
  地の文に詰め込まれ、視認性が低かった（style-guide 3.6節の比較表ルールに未整合）。
- **大**: 「DLP」の初出（2.3節冒頭）から正式定義（DLPとの役割分担小見出し）まで40行以上開いており、
  初出時の補足がなかった。
- **大**: 「変換ルール」という語が、中核概念「補助的統制」との関係を説明されないまま2.4節・7節に
  登場していた。
- **軽微**: Google Cloud SDPの段落が自社への含意（層B候補への接続）まで書かれておらず、Purviewの
  段落と非対称だった。定義表の文言が用語集とほぼ逐語重複していた。

### Codex (`codex exec`) の指摘

上記と同じ3件（主要統制の揺れ／Google Cloud出典の不整合／トークン化定義の不一致）に加え、
以下を独自に指摘。

- **大**: 2.3節の「手動運用が続かない」「過検知で品質を損なう」「シャドーAIを誘発する」が事実調で
  書かれ、出典も「本プロジェクトの見解」ラベルもなかった。
- **大**: 「層AにはDLP・入力前マスキング機能が組み込まれていない」の根拠として引用していた
  [06](../research/06-製品プラン比較.md) に、実際にはDLP・マスキングの比較軸が存在しなかった
  （06はRBAC・SSO等は扱うが、DLP/マスキングは比較対象外）。
- **大**: 2.4〜2.5節がセキュリティ設計に具体的に踏み込んでいるにもかかわらず、style-guide 6節が
  求めるインラインの専門家確認注記がなかった。
- **軽微**: Microsoft Purviewページの更新日表記（`updated_at: 2026-06-25`）と、Codexが参照した
  表示日が食い違う指摘。再検証の結果、本文の`ms.date`フィールドは2026-05-14であり、`updated_at`
  はGitコミット由来の内部フィールドだったため、読者に見える公開日として2026-05-14に統一した。
- appendix/interim-guideline.mdの雛形整合、READMEステータス表記についても言及（対応は下記参照）。

### 対応（第1巡で反映）

| # | 指摘 | 対応 |
| --- | --- | --- |
| 1 | 主要統制の列挙が3箇所で揺れている | 記事冒頭で「情報分類・利用環境・アクセス制御・契約・監査」の5つを明示的に定義し、2.4節の5軸表（RAG/エージェント文脈での分解）は冒頭5つとの対応関係を明記。2.4節冒頭の統制リストにも契約・監査を追加。2.5節・7節の文言をこの5つに統一。 |
| 2 | Google Cloud Vertex AI出典が本文の主張を裏付けない | 「学習・チューニング・推論」という主張を「学習・チューニング用データセットの発見機能」に縮小し、マスキング・トークン化への言及は別出典（Transformation reference）に分離。ライフサイクル全体への適用は「本リサーチの範囲では確認できていない」と明記。 |
| 3 | トークン化定義が引用元と不一致 | 定義を「暗号鍵ベース（Google Cloud）／対応表ベース」の両方を書き分け、Google Cloudの方式が前者である旨を明記。 |
| 4 | interim-guideline.mdの本文が旧方針のまま | 2節冒頭に主要統制が前提である旨の一文を追加し、見出しを「条件付き（契約プランを前提に、伏せ字を追加すれば使える）」に変更。窓口の相談内容にも契約プラン前提の逸脱ケースを追加。 |
| 5 | Anthropic引用が論理の飛躍 | 「エージェント・ツール権限の文脈における傍証」に限定し、「本節の結論を直接裏付ける出典ではない」旨を明記。 |
| 6 | Purviewの対応状況が表になっていない | 5行の比較表に変換。 |
| 7 | DLPの初出説明がない | 2.3節冒頭の初出箇所に簡潔な定義を挿入。 |
| 8 | 「変換ルール」の用語整理 | 「補助的統制（マスキング等の変換ルール）」に統一し、「変換ルール」を単独で使わないようにした。 |
| 9 | 2.3節の理由に事実/見解ラベルがない | 「本プロジェクトの見解（出典のない運用上の判断）」とラベルを追加。 |
| 10 | [06]がDLP/マスキング非対応の根拠として不適切 | 「本リサーチの範囲では確認できていない」＋「06の統制機能比較にも当該項目はない」という正確な表現に修正（3箇所）。 |
| 11 | 2.4〜2.5節にインライン専門家確認注記がない | 2.5節末尾に「本節で扱った統制の組み合わせは自社のセキュリティ要件を満たすことを保証するものではなく、最終的な充足可否は自社のセキュリティ責任者・法務に確認すること」を追加。 |
| 12 | Purview更新日の食い違い | `ms.date`（2026-05-14）を公開日として統一表記。 |

軽微指摘のうち、Anthropic引用範囲の精度・Google Cloud SDPの自社含意・定義表と用語集の重複は、
実害が小さいため今回は見送り、次巡以降で余裕があれば対応する。
