# 00 概要（読み方・前提・原則）

この資料は、非IT中小企業（100〜500人規模）の小規模IT部門が、自社でAI・AIエージェントを
どう導入していくかを整理した解説資料である。結論は明快で、**全社一斉導入を待つのではなく、
まず小規模IT部門自身にAI・AIエージェントを法人プランで導入し、そこで得た実務知見・実測データを
もとに次の展開を判断する**のが、費用・統制の両面でもっともリスクの低い進め方である。次の展開は
「全社拡大」「Enterprise化」「Bedrock/Foundryのような自社クラウド経由の追加導入」のどれか一つを
選ぶ択一の判断ではなく、**「利用範囲の拡大」「層A（法人SaaS）の契約形態変更（Enterprise化）」
「層B（Bedrock/Foundry等）の導入」という3つの問いを独立に判断し、必要なら併用する**（詳細は
[11](11-段階導入ロードマップ.md)3.2節）。すでに
個人アカウントでのAI利用（シャドーAI）が広がりつつある以上、「導入するかどうか」を検討している
間にも無管理の利用は進む。したがって論点は「導入するか否か」ではなく「無管理のまま放置するか、
統制のもとで始めるか」であり、後者を選ぶなら、統制の効く小集団である小規模IT部門から始めるのが
最も速く安全な着手点になる。

本記事（00）は、この結論に至る各論の詳細には立ち入らない。この先を読み進める前に共有しておきたい
前提・原則と、読み方の地図を示す。各論の根拠・実務的な詳細は[01](01-導入判断.md)以降の各記事に
譲る。記事ごとの想定読者・扱う論点は[記事インデックス](README.md)を参照してほしい。

## この資料の前提・読み方

- **想定する進め方**: 全社一斉導入ではなく、小規模IT部門がまず自部門にAI・AIエージェントを
  導入する。そこで得た知見をもとに次の展開を判断する（[01](01-導入判断.md)、
  [11](11-段階導入ロードマップ.md)）。
- **導入するプランと対象**: Claude Team等の法人プランを想定し、対象は文章・調査・整形・コード
  など汎用作業から始める。個人情報・機密データを扱う業務は対象外（[01](01-導入判断.md)、
  [05](05-セキュリティ法務調達.md)）。
- **統制の骨格**: 最初に共有しておきたい統制の骨格は3つ。情報区分に基づく入力可否ルールと
  マスキング運用、コネクタ許可制・最小権限設計、測定指標を先に決めてから始めること（詳細は
  [04](04-ガバナンス.md)・[05](05-セキュリティ法務調達.md)・[08](08-IT部門向けAIエージェント.md)・
  [10](10-パイロット運営.md)）。
- **見直しのタイミングの考え方**: 一定期間後、実測データをもとに次の段階を判断する。この
  進め方そのものを最初に決めておく（[11](11-段階導入ロードマップ.md)）。大事なのは「測定して
  から判断する**手順**を先に決めておくこと」であり、「Enterprise化する」「Bedrock/Foundry
  を導入する」という**特定の結論**をあらかじめ決めることではない。判断は単一の4択でも
  層A/層Bの2つに集約するのでもなく、「利用範囲の拡大」「層Aの契約形態変更（Enterprise化）」
  「層Bの導入」という**3つの問いを独立に見るGo/Hold/Stop判定**で行う。3つの問いは対等な選択肢で、
  この時点ではどれも既定路線にしていない（判断基準の詳細は[11](11-段階導入ロードマップ.md)3.2節）。
- **費用の考え方**: 座席単価に対して必要な削減時間はわずかで、損益分岐点は低い水準にあるという
  考え方で試算する（詳細な試算式・数値例は[02](02-費用対効果.md)）。

## 1. 想定読者と環境

- 非IT中小企業（100〜500人）。社内SE部門5〜15名、専任の情報システム部門というより兼務中心の小規模IT部門であり、開発主体ではない。
- 全社導入はハードルが高く、まずIT部門で小規模導入して効果を最大化したい。
- Claude 導入を主に想定（Codex/OpenAI も同等に扱う）。

## 2. なぜ今、小さく始めるのか

### 2.1 4段階モデル

AI活用は、①チャットのような個人利用から、②社内情報に基づく回答・資料生成、③ツールを使った
自律的な複数手順の実行、そして④業務プロセスの構造自体がAIの存在を前提に組み替わる段階へと、
組織の理解と統制の成熟に応じて広がっていく。

これは業界標準のフレームワークではない。本プロジェクトの記事群が全体のどこに位置するかを
示すための簡易的な整理である。**①〜③の範囲では**、段階を飛ばす（例: 個人利用の実績が薄い
部署がいきなり③のエージェント活用から着手する）、複数段階を並行して進める、部署によって
到達段階が違う——そうした展開も普通に起こる。ただし④は性質が異なり、原則として①〜③の
実務知見を土台として初めて到達できる段階であるため、この「飛ばしてよい」範囲には含まない
（例外の扱いは本節後段を参照）。

| 段階 | 何をするか | 関連記事 |
| --- | --- | --- |
| ① チャット | 調べもの・文章作成・要約など、個人による単発の質問応答 | [01](01-導入判断.md)・[02](02-費用対効果.md) |
| ② RAG・ファイル生成 | 社内文書・データに基づいた回答や資料の生成 | [03](03-効果とDX.md)3節 |
| ③ エージェント | 人が指示した目的に対し、ツール・コネクタを使って複数手順を自律的に実行（部署内の複数システムを横断した棚卸し・状況可視化を含む） | [08](08-IT部門向けAIエージェント.md) |
| ④ 業務プロセスの再設計（AI前提） | AIが横断的に状況を把握できることを前提に、既存の業務プロセスの構造自体（役割分担・判断の順序・承認の要否）が組み替わる | パイロットの対象外（下記参照） |

コーディングエージェント（[09](09-コーディングエージェント.md)）は、この4段階のどこか一段に
一対一で収まる位置づけではなく、コード生成・レビューという特定領域に対して①（単発の質問応答）
から③（複数手順の自律実行）までの成熟度が並行して現れる**別トラック**として扱う。小規模IT部門は
上表の汎用領域の段階とは別に、コーディングエージェントの活用度合いも合わせて棚卸しするとよい。

今回提案する小規模IT部門限定パイロットが対象にするのは**1〜3段階**まで。**4段階目
「業務プロセスの再設計（AI前提）」は、今回の投資判断の対象に含めない。** これは全社規模の
話に限らず、小規模IT部門内でのプロセス再設計であっても同じ扱いにする。次に進むかどうかは、
[11](11-段階導入ロードマップ.md)の見直しのタイミングを経て検討する将来の方向性として
位置づける。

④に到達するかどうかは、この資料のテーマではない。ただし**本プロジェクトの見解**として、
①〜③の実務知見が薄いまま④に着手するのは推奨しない。④に必要な統制設計（情報を同じ形で扱う
仕組み、権限設計、業務プロセスの見直し）は、通常は①〜③で得た実務知見の上に積み上げるのが
安全である（[05](05-セキュリティ法務調達.md)2.4節）。ただしこれは全ケース一律の絶対条件では
ない。他部署・他プロジェクトで①〜③相当の実務知見（権限設計・情報基盤整備の経験等）を既に
持つ組織であれば、④の前提条件を自社の実績で満たせるかを確認したうえで、段階を圧縮して
進めることもあり得る。

### 2.2 RAG・ファイル生成の対象範囲

今回の小規模IT部門限定パイロットが②の段階として想定するのは、
既存のファイル参照機能等を使って手元の資料をAIに読み込ませる程度の使い方であり、専用の検索基盤・
ナレッジベースを新規に構築する大掛かりなRAG基盤整備は含まない。ナレッジ構造化を含む本格的な
情報基盤整備は[03](03-効果とDX.md)3節が示す発展目標であり、着手の要否・範囲は自社の状況に応じて
別途判断する（現時点で[10](10-パイロット運営.md)・[11](11-段階導入ロードマップ.md)に本格RAG基盤
整備専用の成果物・測定指標は設けていない）。

### 2.3 シャドーAIは検討を待ってくれない

個人アカウントでのAI利用（シャドーAI）は、①の段階としてすでに起きている可能性が
高い。[01](01-導入判断.md)3.1節が示す通り、この現状は「導入するかどうか」の検討を待ってくれない
（出典は同節を参照）。①を無管理のまま放置するか、統制のもとで①〜③の足場を作るか
——この論点は次の節で整理する。

### 2.4 実例：段階を追って適用範囲を広げた企業

「チャット導入から始め、段階を追って適用範囲を広げる」という進め方は、実在の日本企業でも
見られる。三井不動産は2025年10月にChatGPT Enterpriseを全社員に導入し（約500件のカスタムGPTが
運用）、2025年12月には経営層向け「社長AIエージェント」の全社トライアルを開始、「DX本部長
AIエージェント」でDX推進部門員の資料作成・修正にかかる時間を平均で約30%削減する成果を上げた。同社は今後、
「社内データの整備・活用」「経営の意思決定支援」へと適用範囲を段階的に拡大していく方針を示している
（[三井不動産「社長AIエージェントなど独自AI開発と、全部門で150名のAI推進リーダーを設置」][ref-mitsuifudosan]、
2025-12-23付、確認日: 2026-07-14）。ただし「経営の意思決定支援」は同社にとってもまだ実現済みの
成果ではなく今後の方針として示されている段階であり、これは特定製品の推奨根拠ではなく、
「段階を追って適用範囲を広げる」という進め方自体が実在企業で行われていることを示す事実として
引用する。

## 3. 本プロジェクトの立場

- 論点は「導入 vs 不導入」ではなく「**無管理の利用 vs 管理された利用**」（→ [01](01-導入判断.md)）。
  すでに個人アカウントでの利用（シャドーAI）が起きているなら、不導入という選択肢は
  実質的に「無管理のまま放置する」ことを意味する。
- [05](05-セキュリティ法務調達.md)が整理する通り、「学習しない法人プラン」でも**社外送信そのもの**は残る。ポリシーは後者基準で設計する。
- IT部門が触っていないのに、エージェントの提案・設計・リスク評価はできない。まず小規模IT部門限定で
  導入し知見を上げ、次段階（Enterprise / Bedrock / Foundry）を見直しのタイミングで決める
  （→ [11](11-段階導入ロードマップ.md)）。契約形態の変更（Enterprise化）や層Bの追加導入は
  費用・法務面での影響が大きい投資判断であり、最終判断は自社の状況を踏まえた専門家・内部確認を
  経ること。

## 4. 反論への回答（想定される質問）

| 想定される反論 | 回答 |
| --- | --- |
| 社内情報を外部AIに出すのは危険では | 学習利用と社外送信は別問題。[01](01-導入判断.md)2.1節・[05](05-セキュリティ法務調達.md)が示す通り、法人プランは学習に使わない前提で、他のクラウドサービスと同じ基準（開示リスク）で管理可能 |
| 精度が不安・誤りが混ざるのでは | 下書き・レビュー前提の用途から始め、無検証で使わない運用にする（[01](01-導入判断.md)2.2節） |
| うちの業務は特殊でAIが向かないのでは | 汎用作業（文章・調査・コード）は業種非依存で効果が出やすく、そこから着手する（[01](01-導入判断.md)1.3節） |
| 費用に見合うのか | 座席単価に対し必要な削減時間はわずかで、損益分岐点は低い水準にある試算。詳細な試算式・数値例は[02](02-費用対効果.md)を参照。実測値は3〜6ヶ月後の判断材料にする |
| 小規模IT部門限定は中途半端では | 妥協ではなく、次の投資判断に必要な知見を集める情報収集フェーズという設計（[06](06-製品プラン比較.md)3節、[11](11-段階導入ロードマップ.md)1節） |
| どうせ全社のシャドーAIは解決しないのでは | その通りで、小規模IT部門限定導入だけでは解決しない。全社的な統制は別途必要（[01](01-導入判断.md)3.3節、[04](04-ガバナンス.md)）。ただしまず小規模IT部門が統制の実務知見を持つことが前提になる |
| ただでさえ忙しい小規模IT部門に、教育・運用・測定までやる余裕があるのか | 強制利用ではなく希望者から開始し、運用工数（教育・例外対応・月次測定）は次の段階に進む場合にも必要になる知見を先取りする投資と位置づける（[02](02-費用対効果.md)3節、[10](10-パイロット運営.md)1.4節） |
| 教育・運用が定着せず利用率が上がらないのでは | 利用率低迷を明示的な停止条件の一つとしてあらかじめ定義する（[10](10-パイロット運営.md)1.3節） |

## 5. 検討のポイント・次のアクション

- 何を測り、いつ導入前値・事後値を取るかという具体的な進め方は、[11](11-段階導入ロードマップ.md)の
  「導入スケジュールの例」を出発点にして、自社の体制・日程に置き換える。本資料はスケジュールを
  代わりに決める立場になく、進め方の型を示すだけである。
- 3〜6ヶ月後、その実測データをもとに次の段階を判断する。判断は単一の4択ではなく、
  「利用範囲の拡大」「層Aの契約形態変更（Enterprise化）」「層Bの導入」という3つの問いを
  独立に見るGo/Hold/Stop判定で行う（[11](11-段階導入ロードマップ.md)3.2節）。
- 社内で合意形成する際は、この資料の内容を稟議書の形式に落とし込んだ雛形
  （[付録](appendix/ringi-draft.md)）を出発点として使える。ただし本資料は汎用解説であり、
  導入・Enterprise化・層B導入といった投資判断の最終決定は、自社の状況を踏まえて法務・情報
  システム部門・外部専門家等に確認したうえで行うこと。

## 記事末尾の成果物

- **4段階の自己診断チェックリスト**: 自社が現在どの段階にいるかを棚卸しする簡易シート。
  1. チャット利用（個人の調べもの・文章作成）は、許可された形で行われているか（シャドーAIに
     なっていないか）。
  2. RAG・ファイル生成（社内情報に基づく回答・資料生成）の実績はあるか。ナレッジは整理されているか。
  3. エージェント（コネクタ・複数手順の自律実行）を試したことはあるか。権限設計はできているか。
  4. 業務プロセスの手順・承認・役割分担そのものを組み替える構想（④段階への足がかり）について、
     検討・着手し始めているか（していなくても、今回のパイロット段階では問題ない）。
