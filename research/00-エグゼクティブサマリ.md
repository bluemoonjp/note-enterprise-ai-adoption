## 要約（結論先出し・1ページ相当）

**結論**: 小規模IT部門限定で、法人プラン（Claude Team等）を使ったAI・AIエージェントの
パイロット導入を承認してほしい。全社展開ではなく、まず小規模IT部門自身が使い、3〜6ヶ月後に
実測データでEnterprise化・Bedrock/Foundry等への投資判断を行う。

**なぜ今か**: すでに個人アカウントでのAI利用（シャドーAI）が社内で起きている可能性が高い。
これは「導入するかどうか」の議論を待ってくれない、**現在進行形のリスク**である
（[01](01-導入判断.md)）。業界的にも、AI・AIエージェントは「使うかどうか」の段階を
超えて基盤化が進んでいる（2節）。

**推奨案**: 小規模IT部門（想定5〜15名）限定で、Claude Team等の法人プランを正式導入する
（[06](06-製品プラン比較.md)）。対象は文章・調査・整形・コードなど汎用作業から開始し、
個人情報・機密データを扱う業務は対象外とする（[01](01-導入判断.md)、[05](05-セキュリティ法務調達.md)）。

**主要リスクと対策**:
- 情報区分に基づく入力可否ルールとマスキング運用で、社外へのデータ送信を管理する（[05](05-セキュリティ法務調達.md)）。
- コネクタ許可制・最小権限設計で、エージェント固有の権限越境リスクを管理する（[08](08-IT部門向けAIエージェント.md)）。
- 測定指標とHold/Stopの判断基準を先に決めてから始める。「導入すれば自動的に投資回収できる」という
  前提には立たない設計である（[11](11-段階導入ロードマップ.md)）。
- 希望者からの段階的開始とし、教育・運用工数はEnterprise展開時にも必要になる知見を先取りする
  先行投資として位置づける（[02](02-費用対効果.md)3節、[10](10-パイロット運営.md)1.4節）。
- 利用率低迷を明示的な停止条件の一つとし、教育・運用が定着しているかを早期に把握する（[10](10-パイロット運営.md)1.3節）。

**概算費用**: 小規模IT部門10名がClaude Team Standardを利用した場合、月額はおおむね**3万円程度**
（座席単価 約3,000円 × 10名の概算例。自社の実際の座席数・為替レートで再計算が必要、試算方法は
[02](02-費用対効果.md)4.3節）。座席あたり月1人時程度の効果があれば費用は回収できる計算になる
（[02](02-費用対効果.md)4節）。**この試算は文章・調査等の一般用途が対象で、コーディングエージェント
（[09](09-コーディングエージェント.md)、別トラック）の運営・効果測定コストは含まない**。Claude Code自体は
同じTeam Standard席に含まれるため、対象者が上記10名と重なる場合は追加のライセンス費は生じないが、
利用量次第でTeam Premium等への引き上げが必要になる場合がある（[06](06-製品プラン比較.md)2.3節）。

**次の90日**: 30日で初期設定・教育と、5指標（[10](10-パイロット運営.md)、
[11](11-段階導入ロードマップ.md)3節）のうちベースラインを持つ指標（時間削減・シャドーAI利用）の
導入前値記録を完了し、60〜90日で事後値・都度記録の指標（入力の詰まり・権限越境・他部署要望）を
計測して中間集計する。3〜6ヶ月後、その実測データをもって
次の投資判断（Enterprise化／Bedrock・Foundry検討／現状維持／中止）を行うことを、
**この提案の時点であらかじめ約束する**。

## 1. 想定読者と環境

- 非IT中小企業（100〜500人）。社内SE部門5〜15名、専任の情報システム部門というより兼務中心の小規模IT部門であり、開発主体ではない。
- 全社導入はハードルが高く、まずIT部門で小規模導入して効果を最大化したい。
- Claude 導入を主に想定（Codex/OpenAI も同等に扱う）。

## 2. なぜ今、AI・AIエージェントなのか（業界の潮流）

- Microsoft CEOのSatya Nadella氏は、2026年6月のMicrosoft Build基調講演で、
  「本当の意味でのプラットフォームシフトが起きている。OSやアプリ向けデバイスを作ることから、
  エージェントへと移行している」という趣旨の発言をしている
  （[Microsoft "The Source" Build Keynote Transcript][ref-nadella-build2026]、確認日: 2026-07-13）。
- 同氏は2026年1月の世界経済フォーラム年次総会（ダボス会議）でのBlackRock CEO Laurence Fink氏との
  対話でも、「AIは組織内の情報の流れ方そのものを逆転させる。それを踏まえれば、既存の業務構造は
  もはや意味をなさないため、業務構造自体を作り直す必要がある」という趣旨の発言をしている
  （[Fortune「Microsoft CEO Satya Nadella's biggest AI bubble warning yet is a challenge to the
  Fortune 500」][ref-nadella-davos2026]、2026-01-20付、確認日: 2026-07-13）。これは「ツールを
  導入するだけでは効果は出ず、部門横断の情報の流れ・業務プロセスの組み替えまで踏み込んで初めて
  効果が出る」という本プロジェクトの立場（[02](02-費用対効果.md)4.4節、[03](03-効果とDX.md)）とも
  整合する。
- Gartnerは、2026年末までに**エンタープライズアプリの40%がタスク特化型AIエージェントを
  搭載する**と予測している（未満5%からの急増、[Gartner「Gartner Predicts 40% of Enterprise Apps
  Will Feature Task-Specific AI Agents by 2026」][ref-gartner-40pct]、2025-08-26付、確認日: 2026-07-13）。
- 一方で同社は、**エージェント型AIプロジェクトの40%超が2027年末までに中止される**とも予測しており
  （[Gartner「...Agentic AI Projects Will Be Canceled by End of 2027」][ref-gartner-cancel]、確認日: 2026-07-13）、
  「導入すれば自動的にうまくいく」わけではないことも同時に示されている。本プロジェクトが
  小規模パイロット・測定先行の進め方を推奨するのは、この失敗パターンを避けるためである
  （[02](02-費用対効果.md)4.4節、[11](11-段階導入ロードマップ.md)）。

以上はいずれも自社の判断根拠そのものではなく、**「なぜ今議論する価値があるか」の背景**である
（判断根拠は自社のパイロット実測値を優先する、[02](02-費用対効果.md)4.4節）。

## 3. 本プロジェクトの立場

- 論点は「導入 vs 不導入」ではなく「**無管理の利用 vs 管理された利用**」（→ [01](01-導入判断.md)）。
  すでに個人アカウントでの利用（シャドーAI）が起きているなら、不導入という選択肢は
  実質的に「無管理のまま放置する」ことを意味する。
- 「学習しない法人プラン」でも**社外送信そのもの**は残る。ポリシーは後者基準（→ [05](05-セキュリティ法務調達.md)）。
- IT部門が触っていないのに、エージェントの提案・設計・リスク評価はできない。まず小規模IT部門限定で
  導入し知見を上げ、次段階（Enterprise / Bedrock / Foundry）を判断ゲートで決める（→ [11](11-段階導入ロードマップ.md)）。

## 4. 反論への回答（想定される質問）

| 想定される反論 | 回答 |
| --- | --- |
| 社内情報を外部AIに出すのは危険では | 学習利用と社外送信は別問題。法人プランは学習に使わない前提で、他のクラウドサービスと同じ基準（開示リスク）で管理可能（[01](01-導入判断.md)2.1節、[05](05-セキュリティ法務調達.md)） |
| 精度が不安・誤りが混ざるのでは | 下書き・レビュー前提の用途から始め、無検証で使わない運用にする（[01](01-導入判断.md)2.2節） |
| うちの業務は特殊でAIが向かないのでは | 汎用作業（文章・調査・コード）は業種非依存で効果が出やすく、そこから着手する（[01](01-導入判断.md)1.3節） |
| 費用に見合うのか | 座席あたり月1人時程度の削減で費用は回収できる試算。自社の実測値で3〜6ヶ月後に検証する（[02](02-費用対効果.md)） |
| 小規模IT部門限定は中途半端では | 妥協ではなく、Enterprise/Bedrock投資判断に必要な知見を集める情報収集フェーズという設計（[06](06-製品プラン比較.md)3節、[11](11-段階導入ロードマップ.md)1節） |
| どうせ全社のシャドーAIは解決しないのでは | その通りで、小規模IT部門限定導入だけでは解決しない。全社的な統制は別途必要（[01](01-導入判断.md)3.3節、[04](04-ガバナンス.md)）。ただしまず小規模IT部門が統制の実務知見を持つことが前提になる |
| ただでさえ忙しい小規模IT部門に、教育・運用・測定までやる余裕があるのか | 強制利用ではなく希望者から開始し、運用工数（教育・例外対応・月次測定）はEnterprise展開時にも必要になる知見を先取りする投資と位置づける（[02](02-費用対効果.md)3節、[10](10-パイロット運営.md)1.4節） |
| 教育・運用が定着せず利用率が上がらないのでは | 利用率低迷を明示的な停止条件の一つとしてあらかじめ定義する（[10](10-パイロット運営.md)1.3節） |
